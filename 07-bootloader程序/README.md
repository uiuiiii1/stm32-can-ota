# 07-bootloader程序（接收板 bootloader）

接收板的"换装车间"。上电最先运行（链接基址 0x08000000，占用 16KB），负责三件事：

1. 读 AT24C64 0x20 处的升级记录（状态 + 密钥 0x5A6B）；
2. 状态为 `01`（待升级）时，把 W25Q64 暂存区的固件搬运到内部 flash 的目标分区，读回校验通过后清除标志；
3. 跳转到 app（0x08008000）或出厂程序区（0x08004000）。

目标分区的路由规则：读固件向量表的复位入口地址，落在哪个区就烧哪个区（0x08008000 app 区 / 0x08004000 出厂区），编错基址的镜像会被直接拒收。

## 按键行为（PB12）

| 操作 | 效果 |
|---|---|
| 无操作 | 上电 3 秒窗口结束后按标志决定：`01`→搬运升级；`02`→直接跳 app |
| **长按 ≥2s**（窗口内） | 强制跳转 0x08004000 出厂程序区（08-出场设置：串口 start:长度 收 bin 写 app 区，备用升级通道） |

## 串口输出（USART1 9600）

```
=== boot ===
bootloader start
check update
ee:01 5A 6B          ← EEPROM 记录（状态 密钥高 密钥低）
wait key
no key -> app
update               ← 状态为 01 时出现
meta: w25_addr=0x00001000 size=3884
copy ok -> 0x08008000 ← 搬运+读回校验通过，自动清标志
no update
jump app 0x08008000
```

## 编译烧录

- Keil 打开 `MDK-ARM/01-LED1.uvprojx` → Rebuild → LOAD（ST-Link）
- 烧录位置：0x08000000，与 app（0x08008000）共存于同一颗芯片
- 注意：本工程 16KB 分区已用满（16384/16384），修改代码需同步瘦身

## 依赖硬件

W25Q64（SPI1：PA4=CS、PA5=SCK、PA6=MISO、PA7=MOSI）、AT24C64（PB10=SCL、PB11=SDA）、按键 PB12、USART1（PA9/PA10，9600）
