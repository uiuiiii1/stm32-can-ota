# STM32 CAN 总线 OTA 远程升级

基于 STM32F103C8T6 + CAN 总线的固件远程升级（OTA）完整实现：上位机串口入库固件 → 网关经 CAN 分帧下发 → 接收板暂存校验 → bootloader 搬运跳转。

## 系统架构

```
PC(串口助手) ──UART 9600──> ┌─────────────────┐            ┌──────────────────┐
  start:<size> + bin        │  网关 09-app     │            │  接收板 09-app    │
  (裸 bin 文件)             │  @0x08000000     │──CAN 200k──>  @0x08008000       │
                            │  W25Q80 固件仓库  │ 648 帧分发  │  W25Q64 暂存区    │
                            └─────────────────┘            └────────┬─────────┘
                                                                    │ 置标志(EEPROM 0x20)
                                                                    ▼ 复位
                                                            ┌──────────────────┐
                                                            │ 07 bootloader     │
                                                            │  W25Q64→内部flash │
                                                            │  校验→清标志→跳转  │
                                                            └──────────────────┘
```

| 目录 | 角色 | 关键内容 |
|---|---|---|
| `07-bootloader程序/` | 接收板 bootloader（跳转入口） | 读 EEPROM 标志 → W25Q64 搬运 → 跳转 |
| `09-app程序（控制led闪烁）/` | 接收端固件 | CAN 过滤器收 0x100/0x101、接收状态机、按键触发、置升级标志 |
| `09-app程序（控制led闪烁） 网关/` | 网关发送端 | 串口入库模块、CAN 分帧发送、ready 握手 |
| `01-LED1/` | 示例升级对象 app（链接基址 0x08008000） | |

## CAN 传输协议

全部为标准数据帧，多字节数值大端：

| 帧 | ID | DLC | 内容 |
|---|---|---|---|
| BEGIN | 0x100 | 8 | `'BEGIN'` + 固件总长(2B) + 0xFF |
| DATA | 0x101 | 8 | 帧序号(2B, 从 0 递增) + 6 字节固件数据（末帧补 0xFF） |
| END | 0x100 | 8 | `'END'` + 0xFF + 全文字节累加和(4B) |
| ready | 0x102 | 8 | `'RDY'` + 0xFF×5（接收端擦完暂存区后回给网关） |

握手流程：网关发 BEGIN → 接收端擦 W25Q64 暂存区（45~400ms/扇区，期间不可收数据）→ 回 ready → 网关才开始流式发 DATA（5ms/帧）→ END 携带全文字节累加和，接收端比对 + 帧序号连续性双重校验。

固件在 W25 flash 中的布局（元数据大端）：扇区 0 = `[4B 正文起始地址][4B 正文长度]`，正文从 `0x1000` 起。该布局与 07 bootloader 的搬运逻辑约定一致。

## 编译与烧录

- IDE：Keil MDK 5（ARMCC V5），工程文件在各目录 `MDK-ARM/01-LED1.uvprojx`
- 硬件：STM32F103C8T6 最小系统 ×2、CAN 收发器 ×2（120Ω 终端电阻 ×2）、W25Q80（网关）、W25Q64 + AT24C64（接收板）、USB-TTL
- 网关先经串口入库固件：串口助手发 `start:<字节数>` → 等回 `ready` → 发送 .bin 裸文件（勿勾十六进制）→ 见 `done sum=...`
- 接收板按键单击触发一次升级；`ee:01 5A 6B` 表示升级标志已置位，复位即自动搬运跳转

## 完整 OTA 流程

```
接收板(空)按键 ──update──> 网关 BEGIN ──> 接收板擦 W25Q64 暂存区 ──ready──> 网关
网关流式发 648 帧 DATA ──> 接收板校验(序号连续+累加和) ──> 写 W25Q64 + 元数据
                        └──> END(全文累加和) ──> 比对一致 → 写 EEPROM 标志 → 停发 update
复位接收板 → 07 读标志 → W25Q64 搬运到 0x08008000 → 读回校验 → 清标志 → 跳转新固件
```
